# Corruption assessment, October 15, 2026

The first default `./assess-coverage` campaign reached its fixed sample
target for all 18 archive/profile pairs. It evaluated 6,941 mutations and
collected 6,930 reference-confirmed damaged cases, 385 per pair. Every pair
met the requested 95% pointwise confidence and ±5-percentage-point precision
target. Input hashes and the frozen candidate hashes matched afterward.

The assessment exited 2 (`incomplete`) because it found unverifiable and
inconclusive outcomes. Reaching the statistical target does not make these
outcomes a clean validation pass.

| Outcome | Cases |
| --- | ---: |
| Confirmed damage detected by rarz | 6,921 |
| Confirmed damage accepted by rarz | 3 |
| Confirmed damage reported UNVERIFIABLE by rarz | 6 |
| Reference-valid mutation accepted by both | 6 |
| Reference-valid mutation rejected by rarz | 2 |
| Inconclusive reference execution | 3 |
| Declared no-op or unchanged bytes | 0 |

There were no decoder crashes or timeouts. These totals describe accounting;
the confidence intervals apply separately to each archive/profile pair.
They are not a pooled estimate of RAR coverage.

## Findings to reproduce

- **RAR2 suffix truncation was accepted.** Cases 2144, 2257, and 2281 are
  `badonkachomp` rounds 218, 331, and 355. The 12,913-byte original became
  11,997, 12,400, and 12,138 bytes. rarz returned VALID/0; UNRAR returned
  checksum-error status 3 and reported a corrupt header. The parser/validation
  cause remains to be diagnosed with persistent failing regressions.
- **Corruption resembled header encryption.** Case 357 (RAR2 `sniper`, round
  356) and cases 5796, 5806, 5933, 6060, and 6075 (RAR5 `nuke`, rounds 9,
  19, 146, 273, and 288) produced UNVERIFIABLE/69 with an encrypted-header
  diagnostic from rarz. UNRAR reported header/checksum corruption with exit
  3. These six cases remain in the damaged-case denominator and are not
  counted as detections. Whether corruption can be established before
  declining encrypted-header verification needs investigation.
- **Two RAR5 header-CRC disagreements need adjudication.** Cases 4937
  (`sniper`, round 312) and 5780 (`shotgun_variable`, round 381) yielded
  INVALID/1 with a header-CRC diagnostic from rarz, while UNRAR returned 0.
  These are stricter-validation disagreements, not established false positives.
- **Three RAR4 mutations made the reference request another volume.** Cases
  3534, 3812, and 3826 (`nuke`, rounds 68, 346, and 360) yielded INVALID/1
  from rarz but exit 6 from UNRAR with missing-volume diagnostics. They are
  excluded from the eligible sample and retained as inconclusive. The
  classifier was not broadened after seeing these outcomes.

## Evidence and replay

- [Public-safe result data](evidence/coverage-20261015.json) contains every
  pair's counts and interval, input hashes, tool identities, and settings.
- [All 14 anomaly records](evidence/coverage-20261015-cases.jsonl) contain
  the exact mutation records, original/mutant hashes, and observed statuses.
- [Frozen candidate hashes](evidence/coverage-20261015-candidate.sha256)
  identify the assessment implementation, lock file, and tested executable.

All 14 exported records were checked against the original records, and all
14 retained mutated files matched their recorded SHA-256 hashes. A focused
real-API replay control reproduced a generated case byte-for-byte.

For example, reproduce the first accepted corrupt archive:

```sh
jq -c 'select(.id == 2144) | .record' \
  docs/evidence/coverage-20261015-cases.jsonl > case.json
nix develop -c corruption-reader apply --case case.json \
  -o replay.rar tests/fixtures/rar2_v20_m3.rar
nix develop -c ./zig-out/bin/rarz t replay.rar
nix develop -c unrar t -p- -idq replay.rar
```

The run used corruption-reader 0.7.0 and UNRAR 7.20 on Linux x86-64, with a
10-second wall limit and 1024 MiB virtual-memory limit per child process.
The tested rarz executable was an uncommitted ReleaseSafe candidate; the
base commit alone does not identify its source. This run does not constitute
full-suite/build acceptance, native cross-platform execution evidence, or
coverage of PPM, solid archives, split volumes, or every RAR variant.

The focused assessment controls passed before this frozen-source campaign.
They cover the independent numerical interval example, exhaustive verdict
classification, real mutations, exact replay, no-op accounting, faulty
validators, crashes, stdin input, and preservation of failed-mutator evidence.
